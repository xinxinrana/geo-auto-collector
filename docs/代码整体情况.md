# GEO 自动采集插件 — 代码整体情况

> 版本：v0.3.0  
> 整理时间：2026-07-21（含当日修复）  
> 范围：src/、popup、background、storage、export、lib 及 adapter 全览

---

## 1. 项目目标

一个 Chrome Manifest V3 扩展，用于在多个 AI 搜索/对话平台（Perplexity、ChatGPT、Gemini、Claude、豆包、元宝、Kimi）上：

1. 自动输入关键词/提示词；
2. 等待回答生成完成；
3. 采集**正文文本、正文 HTML、引用来源、完整 QA DOM、页面截图**；
4. 按「会话（抽屉）」组织结果；
5. 导出为 ZIP（含 `report.html` + `screenshots/` + `data/` 原始数据）。

## 4. 核心模块说明

### 4.1 `manifest.json`

- **Manifest V3**，Service Worker 作为后台模块。
- 权限：`tabs`、`scripting`、`storage`、`downloads`、`alarms`、`activeTab`、`debugger`。
- host 权限覆盖 7 个平台。
- 当前版本 `0.3.0`；popup.html 里版本号仍显示 `v0.2.0`（需同步）。

### 4.2 `src/background/service-worker.js` — 任务调度中心

| 能力 | 说明 |
|------|------|
| 消息入口 | `GET_STATE` / `START` / `STOP` / `COLLECT_CURRENT` |
| 批量调度 | `runBatch()` 严格串行执行所有 `(keyword × platform)` 组合 |
| 单任务 | `runOneTask()`：复用/创建 Tab → 导航到新会话 URL → 等待加载 → 注入 `common.js + adapter` → 调用入口函数 |
| 仅采集当前页 | `collectCurrentPage()`：对当前活动 Tab 直接调用 `collectXxxPage`，不导航、不输入 |
| 状态机 | 持久化到 `chrome.storage.session`，并主动 `STATE_UPDATE` 推送给 popup |
| 保活 | 长任务期间创建 `geo-keepalive` alarm，每 0.4 分钟唤醒 SW |
| 截图 | 成功后调用四级 fallback：`html-to-image` → `chrome.debugger` → `captureVisibleTab` 裁剪 → 整页滚动拼接 |
| HTML 清洗 | 把结果里的 `<img>` 替换为 `[图片: alt]` 占位，避免导出时图片喧宾夺主 |

### 4.3 `src/background/platforms.js` — 平台注册表

集中管理 7 个平台：

| 平台 | URL 匹配 | 新会话 URL | 全流程入口 | 仅采集入口 | minChars | maxWait |
|------|---------|-----------|-----------|-----------|---------|--------|
| perplexity | perplexity.ai | / | `runPerplexityTask` | `collectPerplexityPage` | 300 | 180s |
| chatgpt | chatgpt.com / chat.openai.com | / | `runChatgptTask` | `collectChatgptPage` | 1500 | 300s |
| gemini | gemini.google.com | /app | `runGeminiTask` | `collectGeminiPage` | 1000 | 240s |
| claude | claude.ai | /new | `runClaudeTask` | `collectClaudePage` | 1200 | 240s |
| doubao | doubao.com | /chat/ | `runDoubaoTask` | `collectDoubaoPage` | 400 | 240s |
| yuanbao | yuanbao.tencent.com | /chat/naQivTmsDa | `runYuanbaoTask` | `collectYuanbaoPage` | 400 | 240s |
| kimi | kimi.com | / | `runKimiTask` | `collectKimiPage` | 400 | 240s |

新增平台只需在此加一项并新建对应 adapter 文件。

### 4.4 `src/content/common.js` — 平台无关原语

注入到目标页隔离世界，挂到 `globalThis.GEO`。

| 函数 | 作用 |
|------|------|
| `sleep` / `rand` | 等待与随机间隔 |
| `isGenerating()` | 通用生成判断：检测 `[data-testid=stop-button]`、`[aria-label*=Stop]` 等 |
| `waitAnswerComplete(opts)` | 等待回答完成的三信号逻辑：曾经生成+停止消失 / 长度稳定 / 超时 |
| `humanType(el, text)` | 拟人输入到 contenteditable/textarea，触发 React 受控组件 |
| `extractCitations(opts)` | 从指定 root 内抓取 http 链接，按域名聚合 |
| `findQANodeByAnchor(query, opts)` | 通用 fallback：通过问题文本反查用户气泡，再找回答节点、算最小公共祖先 |
| `captureNode(target, opts)` | 页面内调用 `html-to-image` 对节点截图 |
| `makeTrace()` / `log()` | 步骤追踪与日志 |

**关键参数 `isGeneratingFn`**：v0.3 新增，允许平台传入自己的生成判断函数（Kimi 已使用），避免通用选择器失效导致提前采集。

### 4.5 `src/content/adapters/*.js` — 各平台适配器

每个 adapter 结构一致：

```js
findInput()              // 定位输入框
findSendButton()         // 定位发送按钮
isXxxGenerating()        // 平台特化生成判断
findLastQA()             // 定位最后一轮 QA
answerRoot(qa)           // 定位答案正文容器
collect(config, ensureComplete, tr)   // 等待+采集
runXxxTask(query, config)             // 全流程入口
collectXxxPage(config)                // 仅采集当前页入口
inferKeyword(qa)         // 推断关键词（用户问题 → title）
```

**设计约定**：adapter 层故意保持每个平台一份独立代码，不按 base class 抽取，方便各自针对 DOM 变化快速调整。

#### 当前各 adapter 状态

| 平台 | 主要选择器/特征 | 备注 |
|------|----------------|------|
| **perplexity** | `main div[role=textbox]`、`button[aria-label="Submit"]`、`.prose.dark\:prose-invert` | 会主动点「来源」展开 |
| **chatgpt** | `#prompt-textarea`、`[data-turn-id-container]`、`[data-message-author-role=assistant]` | 已修复 `answerRoot` 空正文问题 |
| **gemini** | 自定义标签 `user-query` / `model-response` | 侦查完成 |
| **claude** | 待完善 | 仅文档，代码较早期 |
| **doubao** | 侦查完成 | 有快照 |
| **yuanbao** | 侦查完成 | 有快照 |
| **kimi** | `.send-button-container(.stop)`、`.chat-content-list`、`.chat-content-item-assistant` | 已修复 `isGeneratingFn` 问题，answerRoot 已增强 |

### 4.6 `src/storage/db.js` — IndexedDB 封装

数据库名 `geo_collect`，版本 3，三个 Object Store：

- `results`：采集结果（含 `deleted` 软删除、`sessionId`、`runId`）
- `screenshots`：截图 Blob（按 `screenshotId` 存取）
- `sessions`：会话抽屉（标题、创建时间、软删除）

当前活动会话 ID 走 `chrome.storage.local`（`geo_active_session`），popup 与 SW 共享。

### 4.7 `src/popup/popup.js` — 用户界面

- 关键词输入、平台勾选（表单状态持久化到 `chrome.storage.local`）。
- 「开始检测」：把 `START` 消息发给 SW，触发批量任务。
- 「停止」：设置 `stopRequested` 标志，当前任务完成后退出批量循环。
- 「采集当前页面」：对当前活动 Tab 调用对应平台的 `collectXxxPage`。
- 「导出当前会话」：调用 `exportAll(sessionId)`。
- 会话抽屉：展开/折叠、设为当前活动、删除/恢复、显示成功数。
- 进度条与任务日志：失败可点击展开 trace。

### 4.8 `src/popup/export.js` — ZIP 导出

流程：

1. 读当前会话所有未删除结果；
2. 逐条取截图 Blob，写入 `screenshots/`；
3. 生成 `report.html`；
4. 在 `data/` 下为每条结果建文件夹，含 `README.md`、`metadata.json`、`answer.txt`、`answer.html`、`qa.html`、`screenshot.png`；
5. 打包为 `GEO采集_{会话名}_{时间戳}.zip` 并触发下载。

### 4.9 `src/export/html-template.js` — 报告模板

- 按会话分组卡片；
- 正文用 sandbox iframe + `srcdoc` 渲染，保留原始 HTML 样式；
- 引用来源按出现次数排序；
- 截图引用 zip 内 `screenshots/` 相对路径；
- 完整 DOM 默认折叠。

### 4.10 `src/lib/screenshot*.js` — 截图方案

| 文件 | 方案 | 用途 |
|------|------|------|
| `screenshot-node.js` | `html-to-image` 节点渲染 | 首选 fallback，不再重复注入 common.js |
| `screenshot-cdp.js` | `chrome.debugger` + `Page.captureScreenshot` clip | 还原 100%，但弹官方黄条 |
| `screenshot.js` | `tabs.captureVisibleTab` + 滚动裁剪/拼接 | fallback，支持 QA 节点和整页 |

已删除：`html2canvas.min.js`（未引用）、`kimi.js` 里的 `geoGetQANodeSelector`（未调用）。

SW 中调用顺序：node → cdp → visible-tab → fullpage。

## 5. 数据流

### 5.1 批量任务流

```
popup START
    │
    ▼
service-worker.runBatch()
    │
    ├── 生成 tasks[] (keyword × platform)
    ├── 串行 runOneTask()
    │       ├── 复用/创建 Tab
    │       ├── 导航到 newConversationUrl
    │       ├── 等待页面 complete
    │       ├── 注入 common.js + adapter
    │       ├── 调用 runXxxTask(query, config)
    │       │       ├── findInput → humanType → click/Enter
    │       │       ├── sleep 3s
    │       │       ├── collect(config, true, tr) → waitAnswerComplete()
    │       │       └── 返回 { status, text, answerHtml, citations, qaHtml, qaSelector }
    │       ├── sanitizeResultHtml()（替换 <img>）
    │       ├── attachScreenshot() 四级 fallback
    │       └── 返回结果
    ├── saveResult() 入库
    ├── setState() 更新进度
    └── 任务间随机休息 8–15s
```

### 5.2 仅采集当前页流

```
popup COLLECT_CURRENT
    │
    ▼
service-worker.collectCurrentPage()
    ├── 取当前活动 Tab
    ├── 识别平台
    ├── 注入脚本
    ├── 调用 collectXxxPage(config)
    │       ├── login 检查
    │       ├── findLastQA / answerRoot
    │       ├── collect(config, false, tr)
    │       └── 返回结果
    ├── attachScreenshot()
    └── pushCollectResult() 入库 + 追加到状态任务列表
```

**核心采集逻辑一致**：两个入口最终都调用 adapter 内的同一个 `collect()` 函数，区别只在 `ensureComplete` 参数和是否预先输入问题。

## 6. 最近修改记录

### 6.1 Kimi 生成判断修复

**问题**：Kimi 的生成中状态靠 `.send-button-container.stop` 判断，但 `waitAnswerComplete()` 默认使用 common.js 的通用 `isGenerating()`，识别不了 Kimi，导致提前判定完成。

**修改**：
1. `src/content/common.js`：`waitAnswerComplete()` 新增 `isGeneratingFn` 参数。
2. `src/content/adapters/kimi.js`：传入 `isGeneratingFn: isKimiGenerating`。
3. `src/content/adapters/kimi.js`：`answerRoot()` 增强内容容器选择。

### 6.2 ChatGPT 正文为空修复

**问题**：`answerRoot()` 一旦找到 `.markdown` / `.prose` 就立即返回，不校验是否含文本。stop 按钮消失时 `.markdown` 容器可能已挂载但内容尚未渲染，导致返回空节点，`answerHtml/text` 为空。

**修改**：`src/content/adapters/chatgpt.js`
- 对 `.markdown` 候选增加长度校验（不少于 `assistantMsg` 总文本 30%）。
- 去掉容易命中空外壳的 `[data-testid="conversation-turn-"] > div > div` 选择器。
- 兜底最长 div 同样校验长度。
- 若候选都不够长，退回使用 `assistantMsg` 本身（一定包含完整回答）。

### 6.3 截图库无用代码清理

按「删掉没有用的，保留现在在用的」原则：
- **删除** `src/lib/html2canvas.min.js`（未引用）。
- **删除** `src/content/adapters/kimi.js` 里的 `geoGetQANodeSelector`（未调用）。
- **修正** `src/lib/screenshot-node.js`：不再重复注入 `src/content/common.js`，只注入 `html-to-image.min.js`（`common.js` 已由 SW 提前注入）。

## 7. 代码冗余处理结论

已评估 `docs/代码冗余整理.md` 中的冗余项，结论如下：

| 类别 | 处理方式 | 原因 |
|------|---------|------|
| Adapter 层重复 | **保留现状** | 故意设计，每个平台独立一份 adapter，便于针对 DOM 变化快速调整 |
| 截图库死代码 | **已清理** | 删除 `html2canvas.min.js`、未用全局函数、重复注入 |
| 跨模块工具重复（sanitize、pad2、ensureActiveSession 等） | **暂不改动** | 影响面小，改动收益有限 |

## 8. 已知问题 / TODO

1. **popup.html 版本号未同步**：显示 `v0.2.0`，与 `manifest.json` 的 `0.3.0` 不一致。
2. **Claude adapter 较早期**：文档已写，代码未完全跟上 v0.3 的 QA 定位重构。
3. **异常重试**：单任务失败只记录，不自动重试；网络/风控导致的偶发失败需人工处理。
4. **状态清理**：历史任务状态会累积在 storage.session，长期运行后状态体积可能变大。
5. **生产包瘦身**：`dev/` 目录只在开发环境使用，打包时应排除。

## 9. 技术选型

| 层面 | 选型 |
|------|------|
| 扩展框架 | Chrome Extension Manifest V3 |
| 后台脚本 | Service Worker (ES Module) |
| 页面脚本注入 | `chrome.scripting.executeScript` |
| 数据存储 | IndexedDB + `chrome.storage.local/session` |
| 打包导出 | JSZip + URL.createObjectURL + `chrome.downloads` |
| DOM 截图 | html-to-image + chrome.debugger + captureVisibleTab |
| 拟人输入 | `document.execCommand('insertText')` + InputEvent |

## 10. 一句话总结

这是一个基于 MV3 的 AI 平台内容采集扩展，核心思路是 **Service Worker 调度 → 注入平台 adapter → 等待生成完成 → 采集文本/引用/DOM/截图 → 按会话存储 → ZIP 导出报告**。当前 Kimi 生成判断、ChatGPT 空正文、截图库死代码已处理，整体运行稳定，剩余主要是 Claude adapter 完善度和 popup 版本号同步等细节问题。
